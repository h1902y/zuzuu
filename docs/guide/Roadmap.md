# Roadmap

The core was rebuilt greenfield in 2026-06 — the **envelope/note model**, the **four verbs**, the human-gated **loop**, and a concept-filed `src/` (~3.6k lines, zero-dep). What's shipped + verified is documented here; the *why* and the longer arc live in [docs/DESIGN.md](https://github.com/h1902y/zuzuu/blob/main/docs/DESIGN.md) and the build journal [docs/LOG.md](https://github.com/h1902y/zuzuu/blob/main/docs/LOG.md). Live tracking: [issues](https://github.com/h1902y/zuzuu/issues) · [milestones](https://github.com/h1902y/zuzuu/milestones).

## Shipped (verified)
- **The envelope** — one md+frontmatter format; note › module › project; zero-dep parse/serialize; **root-mode** (`zz init --root`, the repo root itself as the Project) alongside classic `.zuzuu/`.
- **The four verbs** — `query` (FTS + graph over a `node:sqlite` index) · `act` (run a note, gated, with a `run.allow` allowlist) · `check` (integrity) · `review` (the human gate). The producer is `observe` (mine real sessions → proposals); `observe-runs` mines `runs.jsonl` the same way.
- **observe (Design B)** — re-parse the transcript, never drive the host; mine recurring commands/files/failures → routed proposals. Adapters for **5 hosts** (Claude Code · Codex · Gemini CLI · OpenCode · pi).
- **Two write lanes, one door** — the agent's writes are gated (`stage` → `zz review`); your own (`note create/delete/set`, CSV/JSON import) land instantly through the SAME single write boundary — validated, provenance-logged, minted. See [[Two Lanes|Two-Lanes]].
- **Guardrails** — the enforced `PreToolUse` gate (rules are notes; fail-open for an interactive operator, **fail-closed for an unattended agent actor**; raw-command matching; ReDoS-guarded).
- **The run safety floor** — every `act`/`flow`/durable-run step gets a clamped timeout, a per-note run lock refuses a second concurrent run, and `runs.jsonl` redacts secret-shaped values.
- **Session management** — session = git branch (the branch *is* the record); per-session worktrees (concurrency); **END holds for the merge gate** (`zz session land`; `autoMerge` opt-in to land on exit); navigable recording markers.
- **The CLI + workbench** — a **two-tier `zz`** veneer over one `api` (flat hot-loop verbs · `note`/`gen`/`session`/`host`/`registry`/`tool`/`secret`/`run`/`trigger` namespaces; every old verb still aliased); **schema-enforced module tables** (a `module.md` `fields` block, 8 field types, computed columns, validates each note at the write boundary); query v2 (`--where` ranges, `--group-by`/`--agg` rollups, saved **views as notes**); module import/export.
- **The workbench: World · Table · Flow** — one screen (`zz host web`), reached through the omnibar (`⌘K`): [[The World|The-World]] (the force-directed map, pending proposals as ghost nodes), the native table (schema-aware grid, the field-config panel), and [[Flow View|Flow-View]] (a workflow's DAG + its runs, read-only, live). The Everything view spans every module; the global page rolls projects up the same way.
- **Tools + toolkits (§I.6, MCP-native reading)** — a module is a toolkit, an action note is a tool; `binding: shell` (built) / `agent` (honestly returns `needsHost:true`, no CLI-side ACP client yet) / `mcp` (clean stub, no client yet). `zz tool list`/`show`. See [[Tools]].
- **Secrets (§J.3/§J.5)** — a `type: secret` note is a declaration only; the value lives on the host (env/`fly`/keychain), never in a note, a log, or an agent's context, enforced at the write door. `zz secret declare/list/show/check`. See [[Secrets]].
- **The durable runner (§I.3/§I.4, Tier 2)** — `zz run start`/`advance`/`signal`/`complete`: the run is a note, pinned to the workflow generation it started under, at-least-once semantics, saga compensation on failure. See [[Workflows]].
- **Triggers as notes (§I rung 4)** — `type: trigger` names a gated, versioned automation with a blast-radius preview; `zz trigger fire` is always explicit, or fired by the opt-in local tick below.
- **Workflow composition (§I rung 1)** — a step may be `note: <module:id>`, composing a leaf action or a nested workflow, cycle-detected.
- **The wake source — an opt-in local tick** (`docs/plans/2026-07-06-001-feat-wake-source-tick-plan.md`) — `zz autonomy on` flips a per-Project, auditable opt-in switch; once on, `zz tick`/`zz web --autonomy`/`zz daemon` fire *enabled* `cron` (zero-dep matcher) and `note-change` triggers on a cadence, idempotently, through the SAME gated `fireTrigger`→`startRun` path a human uses. Unattended runs gate their steps fail-closed (a manual run is unchanged); an `agent`-binding step still can't be spawned unattended (`needsHost:true`). `zz doctor`/`zz autonomy status` surface the switch's position + the last tick's fired/skipped/denied. See [[Workflows]].

## Next
- **Host hook/gate parity** — the lifecycle hook + enforced gate are wired for **Claude Code**; re-wire the per-host enable for Codex (`.codex/hooks.json`), Gemini (`.gemini/settings.json`), OpenCode (plugin), pi (extension). observe already covers all five.
- **Real containment for `act`** — bundle a sandbox (e.g. Anthropic's sandbox-runtime — Seatbelt / bubblewrap) so runs can be OS-isolated, not just gated + allowlisted. (The earlier `contained`/`sandboxed` tier stubs were removed; this would reintroduce containment as a real, opt-in backend.)
- **The MCP client** — the `mcp` tool binding is a stub today (`{ok:false}`, no fake success); dialing a real MCP server and mapping inputs to its tool args is the follow-on build. See [[Tools]].
- **Agent-binding dispatch from a hosted daemon** — the CLI honestly refuses (`needsHost:true`); the ACP lane exists daemon-side (`web/src/server/acp.ts`) but isn't yet wired to tool-binding dispatch.
- **The hosted 24/7 tier + ingress** — the opt-in LOCAL tick (shipped, above) only fires while your machine is awake and something is hosting it; the always-on Fly-hosted tier and `/ingress/<trigger-id>` webhooks (inbound automation with no local door today) remain deferred. See [[Workflows]].
- **`oidc` secret resolution** — accepted at the write door, but the resolver honestly refuses to resolve it from a local CLI process; it's a per-run, host-side lane. See [[Secrets]].
- **Cross-project secret sharing** — scope is within one Project today; a registry-level story (sharing a declaration's shape, never its value) is unbuilt.
- **Conversation mining** — the LLM-judge seam in `observe`: extract durable facts + "avoid X" lessons from the session conversation, not just the command log.
- **Richer Gemini observe** — recover tool spans from Gemini's checkpoint files (it's the one thin host today).
- **Cloud session tier** — container-per-worktree + local↔cloud sync (infra-gated). Design: [session-management roadmap L2→L7](https://github.com/h1902y/zuzuu/blob/main/docs/specs/2026-06-16-session-management-roadmap-l2-to-l7.md) (waves E–H).
- **pi owned harness** — the stage-3 target: granular context/model control, gated on the efficiency benchmark.

## The spine
The product is the loop: **observe → propose → review → write + snapshot** — human-gated, compounding. Everything above is in service of making that loop cheaper to run and richer to feed.
