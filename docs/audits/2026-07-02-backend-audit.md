# Backend audit — zuzuu v1.8.0 as a personal-app substrate (02-07-2026)

> Provenance: deep file-by-file audit (src/notes, src/grow, src/use, src/metal, src/guardrails, src/serve, src/cli, src/sessions) run against the thesis: **"notes are rows in tables that can be CRUDed to build a personal application; the complete experience should be as intuitive as conversing about the project."** Grounded against the first production root-mode vault (~/Documents/personal — 5 modules, 277 notes) and its two live frontends. Companion docs: `2026-07-02-frontend-merge-audit.md`, `2026-07-02-integration-seams-audit.md`, roadmap in `docs/specs/2026-07-02-personal-app-roadmap.md`.

## (a) Strengths — genuinely excellent

1. **The one-writer moat is real, not aspirational.** `grow/commit.mjs` is the sole note-writer and sole minter. Every durable path — `evolve`, `plan/applyPlan`, `refactor`, `rollback`, `edit`, `review.approve` — funnels through `commit()` (`commit.mjs:201`). The comment names the bet: *"there is one door, it validates, it logs, it mints, and it is the only thing that touches the notes"* (`commit.mjs:12-14`). Strongest architectural asset for an app substrate: every write validated, versioned, logged uniformly.
2. **All-or-nothing writes with surgical compensation.** `commit` snapshots pre-images of exactly the touched files, restores in reverse on mid-batch failure (`commit.mjs:167-187, 218-227`). Comment documents the fixed blanket-`git checkout`+`clean` disaster that once *"DELETED every UNTRACKED sibling note"* (`commit.mjs:150-156`).
3. **The read projection is honest about lossiness.** `rows.mjs`: filter/count always in SQL; hydrate the full envelope off disk — *"a custom frontmatter column round-trips perfectly on disk yet is INVISIBLE through the index"* (`rows.mjs:8-11`). Right shape for module-as-table.
4. **FTS injection-safety done properly.** `ftsQuery` (`index.mjs:159-165`) quotes every token, honors trailing-`*` prefix; ranked LEFT-JOIN merges BM25 with id-substring (`index.mjs:186-196`); `, notes.addr` tiebreak on every ORDER BY branch for stable pagination (`index.mjs:224-226`).
5. **Schema validation at the write boundary, schema-aware and tolerant.** `validateNote` checks per-type invariants AND declared typed columns while preserving unknown keys (OKF invariant). `COERCIBLE` table (`validate.mjs:32-41`) is a legible spec. No `fields` = schemaless — progressive formalization.
6. **The command table is the single source of truth** for router + help + daemon argv catalog + guardrail deny-set. `gateWriteVerbPattern()` (`commands.mjs:937`) and `commandCatalog()` (`commands.mjs:883`) derive from the rows the router executes: *"an unlisted command can't exist"* (`commands.mjs:11-13`).
7. **Zero-dep, git-native versioning.** Generations = git commits with `zz-gen:` trailer; rollback is forward motion. Root-mode (`store.mjs:52-66`) is a clean self-describing marker. The YAML-subset parser round-trips exactly, never throws.

## (b) Ranked gaps vs the personal-app thesis

1. **No non-gated create verb; no single-call row create/upsert — form-submit is clunky. (M)** `note` namespace = `view, flow, set, append, rename, fold, retype` (`commands.mjs:400-487`) — no `create`. `note set`/`append` require an existing note (`edit.mjs:21,29`). Only creation path: `stage --op create` then `review approve` — **two process spawns** per row, each paying a full index open. The moat is right for the *agent*; it's overhead for the *human building their own app*. Upsert semantics exist latently in `projectChange` (`commit.mjs:68-71`) but are never surfaced as an operator verb.
2. **Zero reactivity. (M–L)** No fs.watch/EventEmitter/SSE/persistent server anywhere in src/. `serve/` is pure read façades; both frontends poll, paying corpusSig per poll. Needed: index-invalidation signal (corpusSig is the natural cache key), fs.watch or mtime-poll on `items/`, an SSE/event channel from a resident process.
3. **EAV query power is equality-only. (M)** `plan()` (`index.mjs:177-203`) supports only `key=? AND value=?`. Date-range ("activities whose window covers today": `start_date` + `duration_days`) impossible in-engine. Aggregations: only `count(*)` + `moduleCounts`. EAV-column sort hydrates the whole filtered set and sorts in JS (`rows.mjs:66-73`). No cross-module value joins.
4. **corpusSig is O(N) stat-per-open; every façade call opens a fresh connection. (M)** `open(home)` stats every .md per call (`index.mjs:64-79`); every read primitive does open→close. At 10k notes: tens-to-hundreds of ms pure overhead per command, multiplied by polling. Rebuild pays the sig twice (`index.mjs:129` + `:120`). No process-level `{sig, handle}` memoization.
5. **No stable programmatic/server API layer. (M–L)** Bridge imports `src/notes/index.mjs` internals directly (unversioned coupling); daemon shells argv (safe but N spawns, no streaming/transactions). `serve/api.mjs open(cwd)` is the right façade but unreachable except via src/ imports.
6. **Schema layer thin for app-like tables. (M)** 8 field types + `required` + `options`. Missing: defaults, computed/formula fields, unique constraints, per-field description/label/UI hints, enum metadata, typed relation columns, column order. `alterColumn` doesn't backfill — adding `required` makes existing rows invalid on next validate (`schema.mjs:66-78`). Frontends infer columns from present keys (`commands.mjs:76-83`).
7. **Cross-module search exists in the primitive, not the surface. (S)** `search`/`queryData` handle empty module (`index.mjs:197`, `query.mjs:22`) and `readManifest('')` passes the exposure gate (`module.mjs:31`), but CLI `query` requires the module positional (`commands.mjs:203`). Cheap fix.
8. **Missing personal-app primitives (Notion/Airtable/Tana-class).** No direct delete verb (S); no batch stage (S); **no attachments/binary story (L — hard ceiling for a personal vault)**; no import/export (M); no saved views, formulas, rollups, templates-per-type, recurring items, reminders/automations/triggers (L collectively). Closest to automation: `observe` (mines sessions → proposals) and `act`/`flow` (runnable notes) — nothing time-based or data-reactive.
9. **Concurrency & atomicity gaps for the multi-process reality. (M)** No cross-process locking (commit's all-or-nothing is in-process Maps); `writeText` is `writeFileSync`, not temp+rename atomic (`metal/fs.mjs:19`) — a crash can truncate a source-of-truth note; index rebuild race under `journal_mode=OFF, synchronous=OFF` (`index.mjs:42,141-143`) can expose a half-built db to a concurrent reader.

## (c) Latent bugs

1. **Cross-module bare-id relations mis-qualified — backlinks silently lost.** `index.mjs:111` qualifies bare targets to the *source* module: journal→`muscle-group-map` becomes `journal:muscle-group-map` (nonexistent). `related()` finds nothing; `backlinks()` (`index.mjs:285`) misses it; `brokenLinks` (`index.mjs:294-299`) false-flags. Fix: global id→addr map at index build (prefer source module on collision), or resolve at query time. **Load-bearing** for a growing multi-module graph.
2. **`module overview` is M-opens.** `commands.mjs:263` opens a fresh index + materializes up to 10k rows per module for `.length`, when `moduleCounts` (`index.mjs:271`) does it in one query — `digest.mjs:59` already documents this exact fast path.
3. **CLI `query` reintroduces the `--limit 0` bug** fixed at `index.mjs:228-229`: handler does `Number(args.limit) || 50` (`commands.mjs:210`).
4. **`note set` blind-JSON.parses values** (`edit.mjs:17,23`): `zz note set m id title 5` stores number 5. Coercion should be schema-type-aware.
5. **corpusSig computed twice per rebuild** (`index.mjs:129` + `build` at `:120`). Pass the computed sig in.

## (d) Five highest-leverage backend investments

1. **A resident local API server exposing `serve/api.mjs` — read AND write — with an SSE event channel.** Collapses gaps 2/4/5 + half of 1: one long-lived process holds the index handle (kills the stat-walk tax), pushes `{module, generation}` on every commit, becomes the one versioned surface for CLI/daemon/bridge/agents.
2. **First-class operator CRUD verbs: `note create`/`delete`/`upsert` + batch.** Non-gated but operator-only (still through `commit()`, still validated + minted; `agentInvokable: false` keeps the agent moat airtight via the existing table-driven gate). Form-submit → one call.
3. **Query engine v2: range predicates, group-by/aggregations, typed date/number index columns.** `--where key>=v`, `IN`, groupBy/agg (count/sum/avg/min/max); promote declared date/number fields to typed columns so "active today" and rollups run in SQL.
4. **Fix cross-module bare-id resolution (bug 1) + global addr resolver at build time.** Small, load-bearing for the graph's truth.
5. **Schema v2 for app-shaped tables: defaults, labels/descriptions, unique, order, computed.** Enough metadata for the frontend to render real forms and views instead of inferring from present keys; backfills new-row defaults, foundation for saved views/rollups/templates.

Honorable mention: atomic `writeText` (temp+rename) + advisory lock around commit/rebuild — cheap insurance for three processes on one vault.

## Design-language note (the moat vs the second actor)

The codebase frames the moat against a *knowledge-poisoning attacker* (`commit.mjs:11-13`, `review.mjs:6-7`) — an agent-centric threat model. The personal-app thesis introduces a second first-class actor — the human building their own app — for whom the same gate reads as friction, not protection. The `actor`-stamping architecture (`api.mjs:56`, `commit.mjs:211`, `dispatch.mjs:51`) already has the right seam: keep the gate airtight for agents, give the operator a direct, reactive, queryable CRUD surface.
